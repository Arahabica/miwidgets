# Muse Inline Widget 仕様メモ

## 概要

**inline widget** とは、Muse のチャット内の吹き出しの中に HTML を表示できる機能を指す、本プロジェクト上の呼び名である。

> 注意: 「inline widget」は公式名称ではない。公式に名前が付けられている機能ではないため、本プロジェクトで便宜上そう呼んでいる。

本プロジェクトは、この inline widget 向けの HTML テンプレートをまとめていくことを目的とする。

## 制約・仕様一覧

| 項目 | 可否 | 備考 |
|------|------|------|
| HTML の形式 | 1 枚の HTML のみ | 複数ファイル構成は不可 |
| HTML の最大サイズ | 最大 1MB | 目安。インライン化した画像等も含めた総量で考える |
| JavaScript | ✅ 動作する | インライン `<script>` で記述 |
| 外部リソースへのアクセス | ❌ 不可 | 外部 CSS/JS/フォントの読み込みも不可と想定して作る |
| 外部画像リンク | ❌ 不可 | `<img src="https://...">` は表示されない |
| 外部 API 呼び出し | ❌ 不可 | `fetch` / `XMLHttpRequest` 等は使えない |
| インライン化した画像 | ✅ 表示可 | `data:` URI（Base64）や インライン SVG |
| 音声 | ❌ 再生不可 | 音声は流せないとのこと |

## テンプレート作成時のガイドライン

上記の制約から、テンプレートは次の方針で作る。

- **完全自己完結**: CSS・JS・画像をすべて 1 つの HTML 内に収める（`<style>` / `<script>` のインライン記述）。
- **外部依存ゼロ**: CDN のライブラリ、Web フォント、外部画像、外部 API は使わない。
- **画像は埋め込み**: Base64 の `data:` URI かインライン SVG を使う。Base64 は元サイズの約 1.33 倍になるため、1MB 上限に注意する。
- **サイズ管理**: 画像を使う場合は圧縮・縮小し、HTML 全体を 1MB 未満に収める。
- **音声は使わない**: `<audio>` や Web Audio による再生を前提にしない。
- **JS での表現**: インタラクション（タブ切替、カウンタ、アニメーション等）は素の JavaScript で実装する。

## Muse が用意する API・変数

Muse が生成した HTML（`assets/assets_sample.html`）の使い方から分かったもの。公式ドキュメントで確認したものではなく、挙動からの推測を含む。

| 名前 | 用途 |
|------|------|
| `window.hatchWidget.getState(初期値)` | 保存された状態を取得する。無ければ渡した初期値を返す |
| `window.hatchWidget.setState(状態)` | 状態を保存する |
| `hatch-widget-state` イベント | 状態が変わったときに発火。`e.detail.state` に新しい状態 |
| `--hatch-widget-text` | テーマの文字色（CSS 変数） |
| `--hatch-widget-muted` | テーマの補助文字色 |
| `--hatch-widget-border` | テーマの罫線色 |

これらは **Muse 上でのみ存在する**。普通のブラウザで HTML を直接開くと `window.hatchWidget` は未定義になる。

## ブラウザ単体で確認するときの注意

`window.hatchWidget` が無い環境で `getState` を呼ぶとエラーになり、以降の描画が実行されず**真っ白になる**。チャートの中身を JavaScript で生成するテンプレートでは特に起きやすい（中身を静的な HTML に書いたものは、スクリプトが失敗しても静的部分だけ表示される）。

テンプレートには次の対策を入れる。

- `window.hatchWidget` が無ければ、メモリ上で状態を持つ代替を用意する（Muse 上では本物が使われる）。
- `--hatch-widget-*` の CSS 変数には既定色を付ける。例: `var(--hatch-widget-text,#1c1c1e)`。Muse 上では Muse の値が優先される。
- 実行時エラーが見えるよう、スクリプトを `try/catch` で囲み、エラーを画面に出す。
- JavaScript 実行前でも高さが確保されるよう、SVG には `viewBox` と `aspect-ratio` を静的に書く。

## 未確認事項（要検証）

以下は現時点で情報がなく、実機検証で確認したい点。

- 1MB の上限が HTML 文字列のバイト数なのか、他の基準なのか
- 吹き出し内での表示幅・高さの制約（高さは自動拡張か、スクロールか）
- ダークモード / ライトモード対応の有無
- `localStorage` 等のブラウザストレージの利用可否
- `alert` / `prompt` などのダイアログ、リンク遷移（`<a href>`）、フォーム送信の挙動
- `getState`/`setState` の保存場所・保存期間・スコープ・サイズ上限
- Muse 本体（チャット）との双方向連携（ウィジェットからメッセージ送信など）の可否
- CSS アニメーション・`<canvas>`・`<svg>` の対応状況
- クリップボード、フルスクリーンなどのブラウザ API の可否
